## 1. 目标与证据标签

当前目标是学习 ROS2 基础，并沿论文的“平台与通信 → 建图与导航 → 视觉感知与机械臂 → 全流程整合”逐步搭建**近似框架**；不要求与论文硬件或算法实现完全一致。

后续记录统一使用以下标签：

| 标签 | 含义 | 可写成“完成”吗 |
|---|---|---|
| `已核查` | 本次或后续有可复查的命令输出、文件、截图或实验记录 | 仅限被证据覆盖的范围 |
| `文档记载` | 现有文件这么写，尚未在当前环境复验 | 不可直接写成当前完成 |
| `待验证` | 有操作计划，但还没有成功证据 | 不可 |
| `待获取` | 源码、数据或设备尚未进入本项目资料 | 不可 |

## 4. 多 Agent 并行边界

一个 target 由一个负责人拥有；多个 Agent 可分别做只读研究。需要写文件时，先在各自 `plan/<date-goal-slug>/plan.md` 声明 owned 文件。共享文件由整合负责人协调，避免同时修改。

| 工作流 | 可独立交付的内容 | 共享契约 / 交接要求 |
|---|---|---|
| 平台与 ROS 基础 | 环境核查、节点/话题实验记录、仿真启动诊断 | 记录 ROS 发行版、启动命令、输出、时间；不替其他模块宣称可用 |
| 建图与导航 | 地图、参数、导航验收记录 | 明确 `/scan`、`/odom`、`/map` 和 TF 坐标系；地图与 YAML 成对留存 |
| 视觉识别 | 图片来源清单、ArUco/OCR 输入输出与评测 | 明确图像坐标系、标识尺寸、识别结果格式和样本来源 |
| 机械臂与操作 | 仿真模型、规划配置、动作验收 | 明确目标位姿坐标系、动作接口、失败/超时反馈；真机动作需单独验收 |
| 系统整合 | 统一启动、任务顺序、接口兼容检查 | 只在各模块证据足够时提高整体验收状态；共享接口变更先通知各负责人 |

每次交接至少提供：**目标、文件清单、执行命令、实际输出或截图、验证范围、未解决问题、下一负责人需要的输入**。计划写“准备做什么”；`plan/log.md` 只写“实际发生了什么”；可复用经验按参考内核由人决定是否提取。
